# 変換ルール変更ログ

数字→かな変換ルールを固める過程での決定を整理したもの。各行は現行テーブル
（`src/data/single_digit.tsv` / `double_digit.tsv` / `long_digit.tsv`）と突き合わせてある。
ルール本体の考え方は [scoring-rules-blog.md](./scoring-rules-blog.md)、割当分布は [goro-stats.md](./goro-stats.md) を参照。

凡例: ✅ 表に反映済 / ⚠️ 表と差分あり（要対応） / ❌ 不採用・廃止

> 🖼️ **図メモ**: 現行の 1桁/2桁/長音テーブル全体像は [`rules-map.png`](./rules-map.png)（アプリ「その他」タブのルールマップ表示）を参照。変更前後を見せたい場合はこの図の Before/After を並べる。

## 1. 1文字割り当ての廃止 → 2桁化

頻出だが 1桁 single に置いていたものを、思い切って single から外して 2桁 DOUBLE 側に移した。

| かな | 旧（single） | 新（double） | 状態 |
| ---- | ------------ | ------------ | ---- |
| す   | `3`          | `33`         | ✅   |
| つ   | `2`          | `23`         | ✅   |
| む   | `6`          | `63`         | ✅   |

- **「つ」の制約**: 2文字読みとしてなら `23`。**単独の 2桁トークンとしての使用は禁止**。

## 3. 拗音キャリア（ゃ/ゅ/ょ）の収束

小書きの拗音を担う桁は何度も入れ替わり、最終的に **4 / 7 / 8** へ収束。

| 拗音 | 最新の桁 | 例                                        |
| ---- | -------- | ----------------------------------------- |
| ょ   | **X4**   | 14=ひょ, 24=ちょ, 44=しょ, 64=りょ, 94=きょ |
| ゅ   | **X7**   | 17=ひゅ, 27=ちゅ, 47=しゅ, 67=りゅ, 97=きゅ  |
| ゃ   | **X8**   | 18=ひゃ, 28=ちゃ, 48=しゃ, 68=りゃ, 98=きゃ  |

- メモにあった「**X2=ゆ**」は **X4=ゆ の書き間違い**。さらにその X4 も旧版で、**最新は X7**。
- ゆ を拗音側（7）へ寄せたぶん、**single の `7` は思い切って sub=う** を割り当てた。

---

## 4. 2X 過密の調整（ちゃ/ふぁ/にゃ）

`2X` 行に置きたい音が多すぎて競合。逃がし先を決めて確定。

- ふぁ → **58**
- にゃ → **78**
- → 空いた **28 = ちゃ**（`28=ちゃ/つぁ`） ✅

---

## 5. 6X が埋まらない → じゃ 系を投入

`6X`（68=りゃ など）は該当語が見つからなさすぎたため、**じゃ/じゅ/じょ を 6X に相乗り**させた。

- ✅ `64=りょ/じょ`, `67=りゅ/じゅ`, `68=りゃ/じゃ`
- ただし **`48=しゃ` は しゃ のみ**（**48=じゃ は除外**）。じゃ 系は 6X に集約する。

---

## 6. 「ん」（LONG）ルールの変遷

| ルール            | 内容                    | 状態 |
| ----------------- | ----------------------- | ---- |
| X0 → [core]ん     | 各桁の core かな + ん   | ✅ 継続（10=いん, 20=にん, 40=しん, 50=こん, 70=なん, 80=はん, 90=きん） |
| [sub]ん（16,17）  | sub かな + ん を試した  | ❌ **廃止** |

⚠️ **要確認（表との差分）**: 現行 `long_digit.tsv` の **X6 列に [sub]ん が残存**している
（`26=ふん`, `46=よん`, `76=うん`, `86=やん`）。

- 「[sub]ん 廃止」が**全廃**の意味なら → これらは削除対象。
- 16/17 で試した形**だけ**の廃止なら → 現状維持でよい。

あわせて `30=みん`(sub) / `36=さん`(core) は **core/sub が反転**しており、`X0=core・X6=sub` の
原則から外れている（人力最適化の名残）。ここも整理対象か判断が要る。
